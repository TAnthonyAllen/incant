## ORIENTATION — the minimum that makes the tree legible

**Incant** is a reflexive, homoiconic, stack-aware language. Code and data share one
structure: every value, rule, field and instruction is a **`GroupItem`** — a doubly-linked
tree node, Boehm-GC managed. `.twk` is TAWK source and the **source of truth**; `.mm`/`.h`
are generated by `tok` and are **never hand-edited**. `.rtn` files are runtime definitions
`include`d into a `.twk`.

Three languages share this tree — **tok, C++, and incant** — and their syntax bleeds
across files. Before editing a line, confirm which language it is by checking a
known-same-language neighbour. When a build error makes no sense, suspect wrong-language
syntax first.

Read, in this order, and no further unless a claim sends you:
- `CLAUDE.md` — repo orientation and the **bear traps**. The traps are the
  best-evidenced claims in the tree; they carry real error output.
- `docs/genParseSpec.md` — the spec you are converting against.
- `docs/wakeup.md` — current state and the POP ledger.

**Build:** you do **not** build. Run `tok`, run the POPs, diff your target. If you believe
a rebuild is required, say so and stop — foreman holds the build, because the workspace
carries uncommitted work that is not yours and `groups.ext` lives outside the repo.
**Never run `tokall`.**

**Verification doctrine, and it is not negotiable:**
> A POP is not passed unless the process exited **0**. "Expected strings present" is not
> "the run succeeded" — a process can print every correct line, in order, and then die.
> Check `$?`. Verified means *ran*, never *read the source and predicted the shape*.

Commands available to you:
```
tok <File>.twk               # regenerate .mm/.h from tok source
sh genLadder/pop.sh          # every ladder target + census + both baselines
sh genLadder/tree.sh         # the open §2.4 tree fixture
```
`.rtn` files are `include`d into `GroupRules.twk` — edit one, then `tok GroupRules.twk`,
**not** a standalone retok.

## WHAT YOU PRODUCE

### 1. The method
It must reproduce its rung target **byte-for-byte**. The target pins the scope: you may
not shrink the surface to reduce the critique.

### 2. Claim records — the actual deliverable
One per thing you learned about kant that a future round would need. Format:

```
### CLAIM <id>
statement:   one sentence, falsifiable
confidence:  RUN | MEASURED | READ | REASONED | ASSUMED
provenance:  the command, or file:line, or the person who ruled it
asOf:        YYYY-MM-DD
scope:       what this claim does NOT cover
```

| confidence | means |
|---|---|
| **RUN** | a POP proves it; command attached |
| **MEASURED** | read off the live tree once |
| **READ** | read off source, not executed |
| **REASONED** | argued, never checked — *a reader must not act on it* |
| **ASSUMED** | inherited or guessed |

**`scope` is load-bearing.** A claim that holds *conditionally* and does not carry its
condition is worse than no claim: it passes review and traps later. If you cannot state
what a claim does not cover, it is not ready to be written down.

**Grade on your own provenance, never on a neighbour's.** A claim is not RUN because it
sits beside one that is.

You **draft** claims. You do not validate your own — foreman gates, Tony rules on style,
and **the next round is the real test.**

### 3. BLOCKED records — when you cannot express something

```
### BLOCKED <id>
wanted:      what you were trying to express
source:      the C++ being converted
attempts:    at least two, with the ACTUAL OUTPUT pasted
category:    IDIOM-GAP | TOK-BUG | KANT-GAP
```

**Assume in this order — this ordering is the whole mechanism:**

| assume first | | assume last |
|---|---|---|
| **IDIOM-GAP** — you don't know the idiom | **TOK-BUG** — kant expresses it, tok won't compile it | **KANT-GAP** — kant cannot express it |

**Step one on every BLOCKED candidate is to GREP THE TREE for the construct**, before
writing any failing test. A limitation claim dies to a working counterexample faster than
to a new test, and the counterexample carries more — it shows you the idiom, not merely
that one exists. *(On 2026-07-29 a recorded limitation was disproved by shipping code
three functions away that nobody had looked at.)*

A **KANT-GAP** claim requires the failing `tok` run **pasted in** — actual error output,
not an assertion. **⚠ What grade that earns is PROVISIONAL pending SEQ 30a:** a failing
run proves the text did not compile, not that kant cannot express it. Paste it anyway.

**The risk here is inverted from the obvious one.** A real gap announces itself every time
it is hit. A false gap is *self-sealing* — the workaround works, nobody returns, and the
belief is documented as fact.

If you wanted an **iterator** and there isn't one: file it as a BLOCKED-adjacent record
and work around it. Those records are a requirements document written by use rather than
by speculation, and they are wanted.
