/*  invokeK -- RUNG ONE OF THE OPT CHARTER. The kant arm.
    2026-08-13. First live fire of optRK, the optional rule-reference shim.

    THE PICK, AND WHY IT IS NOT THE ONE THE TABLE'S TERM COUNT NAMES.
    SEQ 72's stamped table lists five rules held out by OPT alone. Simplest by
    term count is PrintField at 2 (ExpressioN FormaT?). It is NOT the pick, and
    the override is H7: PrintField's optional is the LAST TERM, so nothing
    follows it that a mis-restored cursor could break. Its absent leg would go
    green with the restore removed -- a rung that certifies nothing.

    InvokE is 3 terms, row  InvokE 3 LR?L no EMITTER term 2 is OPT  and its
    optional sits BETWEEN TWO LITERALS. On the absent leg the ')' must still
    match, which it can only do if the cursor came back. That is the property
    that makes OPT OPT, and this is the shape in which it can fail.

    vs Parens, which has the identical LR?L shape: InvokE's optional callee is
    NamE, Parens' is ExpressioN -- itself a MANY, and Parens is the banked red
    (docs/emitted/parens-red-specimen.txt). Lighter callee, less entangled.

    BOTH LEGS ARE ONE CHARACTER APART IN REAL INPUT:
        fireIt()      the optional NamE is ABSENT
        fireIt(zed)   the optional NamE is PRESENT
    A fixture that fed only the present leg would not have tested the
    vocabulary at all -- it would have tested parseRK, which was already
    certified on SEQ 63.

    ⚠ InvokE FIRES ON EVERY ACTION CALL, which is the widest blast radius any
    rung has taken here. Deliberate: after the bind, `fireIt()`, `fireIt(zed)`
    and `stop()` ALL parse through kpInvokE. There is nowhere for a broken
    door to hide -- a failure takes the file down rather than one row, and the
    sentinel below is what tells the two apart.

    ⚠ ORDER IS LOAD-BEARING, copied from incant/bracedK: the include and the
    bind come BEFORE the define of fireIt, because an action body is parsed
    when it is DEFINED. Otherwise the fixture's own calls would parse through
    the C++ door and this would measure nothing.

    ⚠ THE ARM, NOT THE VALUE. 251 is what the interpreted arm has always
    produced, so a green number proves nothing about which arm answered. Read
    promote=0 (generated, what this rung claims) vs promote=1 (the bind did not
    take). The oracle is incant/invokeKo, which runs the identical work with no
    bind; the two are diffable by design.
*/
